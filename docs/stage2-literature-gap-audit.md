## Current implementation surface checked

- [`src/problems/ritz_certificate.py`](../src/problems/ritz_certificate.py#L46) defines `DiscreteRitzStepCertificate`; [`certify_discrete_ritz_step`](../src/problems/ritz_certificate.py#L248) and [`verify_discrete_ritz_certificate`](../src/problems/ritz_certificate.py#L338) use exact rational interpretations of finite binary32/64 data for a bounded, unconstrained finite-dimensional SPD quadratic. The checker recomputes exact `c` and `q`, validates caller-declared `delta`/`epsilon`, builds an exact trial/lower bound, and replays direct energy difference. It explicitly does **not** establish where the input enclosure radii came from. Feasible callbacks are rejected. This is narrower than a continuous-PDE estimator or a theorem for arbitrary trained candidates.
- [`src/problems/polynomial_poisson_1d.py`](../src/problems/polynomial_poisson_1d.py#L698) builds a replayable exact enclosure record for a restricted polynomial Poisson 1D family; [`verify_polynomial_poisson_1d_enclosure`](../src/problems/polynomial_poisson_1d.py#L762) reconstructs the record and checks the continuous and dyadic targets. It is a bounded analytic family, not a general neural correction protocol.
- [`src/estimators_1d.py`](../src/estimators_1d.py#L30) defines zero-Dirichlet 1D P1 Poisson data with cellwise-constant source; [`EquilibratedFlux1DEstimator`](../src/estimators_1d.py#L139) evaluates exact cell-integration formulae in float64. Its module docstring explicitly says the result is **not an outward-rounded or machine-certified interval bound**.
- [`src/enrichment/pool.py`](../src/enrichment/pool.py#L71) represents a finite `CandidatePool`; [`BestPredictedGainSelector`](../src/enrichment/pool.py#L146) ranks valid positive scores within the supplied pool. Its ratio is chosen score divided by that pool's maximum, not a supremum over an unenumerated or continuous dictionary. [`CEMSolver.step_pool`](../src/solver.py#L137) implements that finite-pool path.
- [`src/strategies/scorer.py`](../src/strategies/scorer.py#L17) provides floating-point strong-residual least-squares, discrete Ritz, and nonlinear-merit scorers. Ritz checks the computed reduction identity within a floating tolerance; the scorer does not emit a verified interval certificate. No current API supplies a general continuous-family coverage bound or a full P4 error recursion.

## Cross-cutting conclusions and claim boundaries

1. **K0 is established background.** Exact energy/Ritz projection and subspace correction identities have extensive antecedents (Xu 1992; Xu–Zikatanov 2002; FNM). A CEM-specific exposition can be useful but should not be positioned as the main novelty without a genuinely new hypothesis/result.
2. **K1 is conditional and not yet an implementation guarantee.** Greedy rates require a specified dictionary, an atomic/variation representation, exact or controlled full correction, and weakness relative to the whole dictionary. `BestPredictedGainSelector` proves none of these from its finite-pool ratio.
3. **P1's algebra is not the gap.** The important missing contribution is a low-cost, independently replayable source for valid `delta`/`epsilon` for the target candidate class, including discretization/quadrature/training error as applicable. The discrete verifier validates declared enclosures but not provenance. The polynomial 1D path closes only its named bounded analytic family. The float64 equilibrated-flux path is not an outward-rounded certificate.
4. **P2/P3 remain genuinely open.** Existing adaptive neural bases, Dörfler marking, random dictionary discretization, and multiscale schemes are close precedents. A finite-pool score ratio is not a continuous-family supremum. Any novelty claim needs explicit Gram/coherence or parameter-covering assumptions and a costed bound; arbitrary heterogeneous-dictionary guarantees are not supported by this source set.
5. **P4/L1 cannot be inferred from software tests or finite examples.** End-to-end bounds require PDE stability, approximation/coverage, reliable candidate gains, quadrature/training and refit errors, plus an operation-level work model. No reviewed paper directly proves the project's full CEM statement; the reviewed papers do establish that several component ideas are not individually new.

These are literature-to-current-API comparisons, not a novelty verdict. In particular, no source in this matrix was used to claim priority over all related work. ## One executable next gate (proposal, not yet implemented)

**Gate:** a bounded, exact 1D P1 Poisson step certificate for conforming piecewise-linear state/correction functions on a strictly increasing dyadic mesh of `(0,1)`, homogeneous Dirichlet data, piecewise-constant source, and binary64 inputs interpreted exactly as dyadic rationals. On every cell, independently assemble exact `c = ∫fφ − ∫u′φ′` and `q = ∫|φ′|²`; reject `q≤0`; compute exact `alpha=c/q` and gain `c²/(2q)`; bind all source, mesh, state and correction inputs in a canonical replayable record. Preserve fail-closed resource caps and do not mutate solver state. This is the smallest bridge from the existing analytic-polynomial fixture toward a source-grounded estimator while keeping the mathematical scope explicit.

**Acceptance evidence:** an independent `Fraction` cell-integral oracle; nonuniform dyadic meshes; both signs of `c`; zero/invalid correction rejection; endpoint/mesh/source validation; signed zero, subnormal and large rational cases; record tampering/replay; one-understated-bound rejection if interval radii are added; deterministic work/size cap tests; direct exact objective-difference equality; and all existing tests/examples on the final source state. Exact cell integrals for this bounded model may be an exact certificate, but do not call the existing float64 estimator outward-rounded.

**Stop/claim boundary:** reject non-dyadic meshes, nonzero boundary data, variable coefficients, nonlinear PDEs, non-piecewise-constant loads, or uncontrolled work until separately specified and proved; do not fall back to an empirical estimate while retaining a certified status. A pass supports only this bounded 1D P1 example. It does not close general P1, K1, P2, P3, P4, L1, convergence, comparative efficiency, or novelty. If this narrow exact path is not a useful project step, record a no-go and revise the gate before implementation rather than broadening silently.
